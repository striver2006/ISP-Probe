# 变更记录

## [未发布]

### 修复

- **测速前补上确认环节**。此前点「开始测速」会直接拿当前 MAC 绑定的那条线开测，
  用户没有选择余地，引导卡片要等第一条测完才出现。现在先停在确认阶段：展示当前
  走的是哪条线、给出改绑入口，由用户点头再开始。停留期间每 5 秒复查出口归属，
  用户此时去路由器改绑，页面会自动更新待测线路，不必退出重来。

### 优化

- **出口归属查询从约 15 秒降到 0.2 秒**。原先首选 `ip-api.com`（国际服务），而这条
  链路在测速确认与切换检测时会反复走。改为国内源 `myip.ipip.net` 优先，并支持解析
  其纯文本格式，归属描述也从 "China Mobile communications corporation" 变为
  "中国 浙江 杭州 移动"。

## [0.1.0] - 2026-09-09

首个可用版本。

### 核心能力

- **零配置分线连通性监控**：经各线路光猫的 LAN IP 发 DNS 查询，包必然从对应 WAN 口出去，
  由该运营商递归 DNS 应答。不依赖路由器的任何分流配置。
- **引导式分线测速**：通过出口 IP 归属识别当前线路，测完一条后引导用户去路由器改绑 MAC，
  自动检测切换完成并接着测第二条。
- **环境自检 `doctor`**：验证 TUN 绕过是否生效、DNS 是否被 fake-ip 污染、分线通道是否可用。
- **本地 Web 面板**：实时状态、延迟趋势、24h 质量统计、测速引导、事件日志（SSE 推送）。
- **桌面通知**：线路故障与恢复时弹系统通知，带抖动抑制。

### 绕过 clash TUN

三层措施，本机实测有效：

- socket 层：macOS `IP_BOUND_IF`(25) / Windows `IP_UNICAST_IF`(31，值需网络字节序)
- DNS 层：只用 DoH，`netbind` 从类型层面拒绝主机名，杜绝系统解析器介入
- 代理层：`Transport.Proxy = nil`

判据用连接的本地端点而非 RTT 对比：绑定后本地端点为物理网卡 IP，未绑定时落在 TUN 网段。

### 故障判定分级

避免把光猫 DNS 限速误报为线路故障：DNS 超时 → ping 光猫排除本地故障 → 降速重试排除限速
→ 才判定线路故障；连续失败达阈值才告警。

### 交叉验证

两条线解析同一域名若返回完全相同的结果，说明流量未被分到不同 WAN，标记分线通道失效。

### 已知边界

- 零配置通道只能测连通性/延迟，测不了分线带宽 —— TCP 走哪条线由路由器决定
- Wi-Fi 链路测速上限受无线速率制约
- Windows + mihomo `strict-route: true` 时，53 端口被 WFP 封禁，分线通道失效
