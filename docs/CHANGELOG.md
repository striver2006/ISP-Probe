# 变更记录

## [未发布]

### 新增

- **线路中断时推送到 IM 群机器人**（企业微信 / 钉钉 / 飞书 / 自定义 webhook）。
  桌面通知在最需要它的场景里恰好是失效的：Windows 服务跑在 session 0 与用户桌面
  隔离，装完还得建议把 `notify.desktop` 关掉改用面板 —— 而「一条线静默失效」本来
  就是无人盯着的场景，要求人去刷面板等于没有告警。发送走绑定物理网卡 + DoH 的
  链路，与探测同一套约束；异步入队，一次 8 秒超时的 HTTP 请求不会拖住探测循环。
  钉钉/飞书的 HMAC-SHA256 加签用标准库实现，未引入新依赖。
  用 `isp-probe notify test` 或面板的「测试」按钮验证配置。
- **持续故障的递增重复提醒**。原先只在状态跃迁时发一条，断一整夜也不再吭声，
  消息被群里刷走就等于没告警过。改为首次告警后第 5/15/30/60 分钟各提醒一次、
  之后每 60 分钟，消息带上已持续时长。刚断时密（人可能就在电脑前），断久了变稀。
  **不写 `events` 表** —— 那张表保持「一次故障 = 一条 down + 一条 up」的忠实记录，
  否则面板事件列表会被重复行淹没。`notify.repeat_alert: false` 可关。
- **旁路配置 `config.local.yaml`**。webhook URL 里的 key 等同于密钥，而 config.yaml
  随仓库提交。旁路文件不进 git，只写要覆盖的字段，存在则叠加到主配置上。
  注意**切片是整体替换而非追加**：旁路里写了 webhooks 就是全量覆盖。
  文件不存在是正常情况；存在却解析失败会报错 —— 静默忽略会让人以为密钥已生效，
  实际一条告警都发不出去。
- **面板可开放到局域网**。`web.listen` 改成 `0.0.0.0:8686` 即可从手机等设备访问，
  配套可选的 `web.token`：留空 = 不鉴权（保持既有行为），设了则非本机请求必须带上
  令牌。本机永远放行，否则 CLI 与单实例自检会被自己的鉴权挡在门外。
  `doctor` 新增一项检查，在开放却没设令牌时告警，并按平台提示防火墙怎么放行。
- **两种运行模式**。除了原有的前台按需运行，现在可以装成随登录自启的后台服务：
  `service install` / `uninstall` / `start` / `stop` / `status` / `logs`。
  macOS 用 LaunchAgent（用户级，无需 sudo，桌面通知可达），Windows 用 SCM 服务
  （管理员权限，延迟自启，三级失败重启）。手写平台代码，未引入新依赖。
- **服务模式日志落文件并轮转**（`logs/isp-probe.log`，默认 8MB × 3）。后台进程的
  stderr 在 Windows 服务里等于丢弃，不落文件就没有排障可能。前台运行仍走 stderr，
  行为与之前完全一致。配置项见 config.yaml 的 `log` 段。
- **单实例保护**。`serve` 加了跨进程锁与端口预检，重复启动会说清占用者是谁、
  怎么处理，而不是抛一句 `address already in use`。`probe` / `speed` 不加锁 ——
  服务跑着的时候，随手看一眼这件事不该被挡住。
- **install 前默认自检**。TUN 绕过没生效时程序不报错、只安静产出假数据，
  而无人盯着的后台服务产出假数据比前台危险得多。`--skip-doctor` 可跳过。
  安装后会轮询面板确认服务真的活着，失败则自动打印日志尾部。

### 修复

- **通配监听下单实例保护会静默失效**。`probeExisting` 直接把 `web.listen` 拼进
  URL，监听 `0.0.0.0:8686` 时得到 `http://0.0.0.0:8686/…` —— macOS 上内核碰巧
  映射到环回而能通，Windows 上直接 `WSAEADDRNOTAVAIL`，于是探测不到已在运行的
  实例，能同时起两个进程抢同一个 SQLite 文件；写成 `:8686` 更是拼出非法 URL。
  新增 `dialTarget` 把「监听所有接口」的写法归一化成可连接的环回地址。
- **关掉桌面通知会让所有通知一起失效**。状态机里的通知门槛写死了
  `cfg.Notify.Desktop`，而 README 恰恰建议 Windows 服务模式下把它关掉 ——
  一旦关掉，新加的 IM 通知也一条都发不出去。开关下沉到构造 Notifier 时决定。

- **测速前补上确认环节**。此前点「开始测速」会直接拿当前 MAC 绑定的那条线开测，
  用户没有选择余地，引导卡片要等第一条测完才出现。现在先停在确认阶段：展示当前
  走的是哪条线、给出改绑入口，由用户点头再开始。停留期间每 5 秒复查出口归属，
  用户此时去路由器改绑，页面会自动更新待测线路，不必退出重来。
- **退出时最后一轮采样不再丢失**。`RunOnce` 的落库阶段沿用了会被取消的 ctx，
  进程退出时 `ExecContext` 立刻返回 `context.Canceled`，本轮已经采到的数据一条
  都写不进去（日志里只留下两行 `写入采样失败`）。改为用 `context.WithoutCancel`
  派生的 5 秒超时 context：探测本身该被取消，写入不该。
- **关闭数据库前会等监控收尾**。`Monitor` 新增 `Done()`，`serve` 据此在关库前
  等待最后一轮写完（上限 8 秒），此前是关了库还可能有写入在路上。
- **配置文件找不到时的报错不再误导**。此前静默回落到默认配置，而默认配置没有
  线路，用户看到的是「配置中未定义任何线路」——与真实原因南辕北辙。现在直接说
  找不到文件，并列出所有尝试过的路径。

### 变更

- **配置查找与路径锚定**。`-c` 不指定时依次在当前目录、可执行文件所在目录查找
  `config.yaml`；`store.path` 与 `log.file` 的相对值锚定到配置文件所在目录。
  服务模式下 cwd 是 `/` 或 System32，相对路径不锚定就会落到那里。
  前台在仓库目录直接跑、`go run` 这两种既有用法行为不变。
- **`config.Load` / `setupIface` 从命令分发前挪到各命令内部**。此前连 `help` 都要
  先读配置、探测网卡，而服务管理命令（`status` / `stop` / `uninstall`）恰恰是
  出问题时要用的，不该依赖这两步。

### 优化

- **出口归属查询从约 15 秒降到 0.2 秒**。原先首选 `ip-api.com`（国际服务），而这条
  链路在测速确认与切换检测时会反复走。改为国内源 `myip.ipip.net` 优先，并支持解析
  其纯文本格式，归属描述也从 "China Mobile communications corporation" 变为
  "中国 浙江 杭州 移动"。

## [0.1.0] - 2026-09-09

首个可用版本。

### 核心能力

- **零配置分线连通性监控**：经各线路光猫的 LAN IP 发 DNS 查询，包必然从对应 WAN 口出去，
  由该运营商递归 DNS 应答。不依赖路由器的任何分流配置。
- **引导式分线测速**：通过出口 IP 归属识别当前线路，测完一条后引导用户去路由器改绑 MAC，
  自动检测切换完成并接着测第二条。
- **环境自检 `doctor`**：验证 TUN 绕过是否生效、DNS 是否被 fake-ip 污染、分线通道是否可用。
- **本地 Web 面板**：实时状态、延迟趋势、24h 质量统计、测速引导、事件日志（SSE 推送）。
- **桌面通知**：线路故障与恢复时弹系统通知，带抖动抑制。

### 绕过 clash TUN

三层措施，本机实测有效：

- socket 层：macOS `IP_BOUND_IF`(25) / Windows `IP_UNICAST_IF`(31，值需网络字节序)
- DNS 层：只用 DoH，`netbind` 从类型层面拒绝主机名，杜绝系统解析器介入
- 代理层：`Transport.Proxy = nil`

判据用连接的本地端点而非 RTT 对比：绑定后本地端点为物理网卡 IP，未绑定时落在 TUN 网段。

### 故障判定分级

避免把光猫 DNS 限速误报为线路故障：DNS 超时 → ping 光猫排除本地故障 → 降速重试排除限速
→ 才判定线路故障；连续失败达阈值才告警。

### 交叉验证

两条线解析同一域名若返回完全相同的结果，说明流量未被分到不同 WAN，标记分线通道失效。

### 已知边界

- 零配置通道只能测连通性/延迟，测不了分线带宽 —— TCP 走哪条线由路由器决定
- Wi-Fi 链路测速上限受无线速率制约
- Windows + mihomo `strict-route: true` 时，53 端口被 WFP 封禁，分线通道失效
